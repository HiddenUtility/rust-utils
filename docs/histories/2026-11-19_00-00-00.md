## 5. Technical Decisions

### Decision 1: Use of `thiserror` for Error Handling

- **Background:** Robust error handling is required for library code.
- **Options:** Manual `Error` trait implementation, `anyhow` (for apps), `thiserror` (for libs).
- **Selected:** `thiserror`.
- **Reason:** Provides a convenient way to define custom error types while remaining lightweight and suitable for libraries.
- **Impact:** Clear, descriptive error messages for users of the crate.

### Decision 2: Implementation of `TryFromDto` Trait

- **Background:** Requirement to separate DTOs from domain models and handle validation/defaults.
- **Options:** Manual conversion functions, `From`/`Into` traits, custom trait.
- **Selected:** Custom `TryFromDto` trait.
- **Reason:** Explicitly signals that the conversion might fail (unlike `From`), which is appropriate for validation logic.
- **Impact:** Ensures domain models are always in a valid state.
