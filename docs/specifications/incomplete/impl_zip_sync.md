# Rust File and Directory Copier (Synchronous) — Codex Implementation Specification

## 1. プロジェクト概要

Rustでファイルおよびディレクトリを安全にコピー・移動する同期型ライブラリクレートを実装する。

以下の3種類のオブジェクトを提供する。

1. `FileCopier`：単一ファイルのコピー・移動
2. `DirectoryCopier`：ディレクトリの再帰的なコピー・移動
3. `FilteredDirectoryCopier`：正規表現による除外設定が可能なディレクトリのコピー・移動

本仕様書では、すべてのファイル操作を同期処理として実装する。

最も重要な要件は、コピー途中でエラーが発生した場合に、既存の出力データを可能な限り維持することである。

### 1.1 基本方針

- Rust Edition 2024を使用する。
- 同期ファイル操作には `std::fs` を使用する。
- 外部クレートは必要最小限にする。
- MIT、Apache-2.0、BSDなどの利用可能なライセンスを優先する。
- Pure Rustのクレートを優先する。
- `std::io::Result<T>` をエラー型として使用する。
- `lib.rs` に実装を集中させず、適切にモジュール分割する。
- 公開APIにはRustdoc形式のdocstringを記述する。
- コメントアウトによる説明は極力避け、docstringで仕様を説明する。
- `src/README.md` を作成し、簡単なドキュメントとサンプルコードを記述する。
- 非同期処理に関するAPIや依存クレートは実装しない。

## 4. 共通仕様

### 4.1 コピー処理の基本原則

すべてのコピー処理は、直接最終出力先に書き込まない。

必ず一時ファイルまたは一時ディレクトリにコピーし、コピーが完了してから最終出力先に反映する。

処理順序は以下とする。

1. 入力パスの検証。
2. 出力先の親ディレクトリを作成する。
3. 既存の一時ファイル・一時ディレクトリがあれば削除する。
4. 一時ファイル・一時ディレクトリにコピーする。
5. コピーが完全に成功したことを確認する。
6. 既存の出力先があれば、バックアップ用のパスにリネームする。
7. 一時ファイル・一時ディレクトリを正式な出力先にリネームする。
8. リネームに成功した後、バックアップを削除する。
9. 移動処理の場合は、最後に元データを削除する。

### 4.2 既存出力先の保護

既存の出力先は、新しいコピーが完成するまで残しておく。

コピー処理の途中で既存の出力先を削除してはならない。

既存出力先の置き換えには、バックアップ方式を使用する。

具体的には以下の順序とする。

```text
1. 既存の出力先をバックアップパスにrename
2. 一時出力先を正式な出力先にrename
3. rename成功後、バックアップを削除
```

一時出力先のrenameに失敗した場合は、バックアップを元の出力先に戻す。

バックアップの復元にも失敗した場合は、両方のエラー内容と対象パスをエラーメッセージに含める。

バックアップパスは、既存ファイルと衝突しないようにプロセスIDと一意な連番などを利用して生成する。

この置き換え方式は可能な限り既存データを保護するものであり、ファイルシステムやOSをまたいだ完全なトランザクションを保証するものではない。

### 4.3 パスの扱い

- パス操作には `PathBuf` と `Path` を使用する。
- ファイル名を文字列として組み立てず、`OsString` を使用する。
- 相対パスと絶対パスの両方を扱う。
- 出力先の最終要素が取得できない場合は `InvalidInput` を返す。
- コピー元と出力先が同一である場合は処理を拒否する。
- ディレクトリコピーでは、出力先がコピー元ディレクトリの内部にある場合も拒否する。
- コピー元の存在確認と種類の検証を必ず実施する。

### 4.4 一時ファイルの命名規則

ファイルの場合は、元のファイル名の末尾に `.temp` を追加する。

例：

```text
data.txt       → data.txt.temp
archive.tar.gz → archive.tar.gz.temp
data           → data.temp
```

拡張子を置き換えてはならない。

実装では `set_extension` による単純な拡張子変更ではなく、ファイル名の末尾に文字列を追加すること。

### 4.5 一時ディレクトリの命名規則

ディレクトリの場合は、ディレクトリ名の末尾に `_temp` を追加する。

例：

```text
backup  → backup_temp
project → project_temp
```

### 4.6 一時データの削除

コピー開始時に、同じ命名規則の一時データが存在する場合は削除する。

- ファイルの一時データ：`remove_file`
- ディレクトリの一時データ：`remove_dir_all`

ただし、対象の種類が想定と異なる場合や削除できない場合は、無理に処理を続けずエラーとする。

コピー処理が失敗した場合は、一時データを可能な限り削除する。

後始末の失敗によって元のコピーエラーを隠してはならない。元のエラーを優先し、後始末の失敗もメッセージに記録する。

### 4.7 エラー仕様

公開APIの戻り値には標準の `std::io::Result<T>` を使用する。

独自のエラー型は作成しない。

エラーを返す際には、処理内容と対象パスが分かるメッセージを付与する。

例：

```text
Failed to open source file: ...
Failed to create destination directory: ...
Failed to copy file to temporary path: ...
Failed to rename temporary file: ...
Failed to restore backup destination: ...
Failed to remove source file: ...
Invalid exclusion regex: ...
```

可能な限り元の `io::ErrorKind` を維持する。

エラーの判別は、標準の `ErrorKind` とエラーメッセージを利用できるようにする。

## 5. FileCopier：ファイルコピーオブジェクト

### 5.1 責務

指定された単一ファイルを、指定された出力先ディレクトリにコピーする。

出力先のファイル名はコピー元のファイル名と同じにする。

### 5.2 構造体

```rust
pub struct FileCopier {
    file_path: PathBuf,
    dir_path: PathBuf,
}
```

### 5.3 コンストラクタ

```rust
impl FileCopier {
    pub fn new(
        file_path: PathBuf,
        dir_path: PathBuf,
    ) -> Self;
}
```

### 5.4 公開メソッド

```rust
impl FileCopier {
    /// 元ファイルを残してコピーする。
    pub fn copy(&self) -> std::io::Result<()>;

    /// コピー完了後に元ファイルを削除する。
    pub fn move_file(&self) -> std::io::Result<()>;
}
```

### 5.5 コピー処理

例えば、

```text
source/
    data.txt

destination/
```

の場合、以下のように処理する。

```text
destination/
    data.txt.temp
```

コピー完了後に、

```text
destination/
    data.txt
```

にリネームする。

### 5.6 出力先ディレクトリ

- `dir_path` が存在しない場合は再帰的に作成する。
- `dir_path` が既存ファイルの場合はエラーとする。
- コピー元のファイル名を取得できない場合はエラーとする。

### 5.7 同名ファイルの置き換え

既存のファイルは一時コピーが完成するまで残す。

一時ファイルが完成した後にバックアップ方式で置き換える。

### 5.8 移動処理

`move_file` は、コピーと最終出力先へのリネームが成功した後に元ファイルを削除する。

元ファイルの削除に失敗した場合はエラーを返す。

この場合、新しい出力先は維持する。

元ファイルがシンボリックリンクの場合は、リンクそのものを削除する。

### 5.9 シンボリックリンク

コピー元がシンボリックリンクの場合は、リンク先をたどらずリンクそのものをコピーする。

`read_link` で取得したリンク先のパスを維持する。

リンク先のファイル内容をコピーしてはならない。

リンク作成はOSごとの標準ライブラリAPIを使用する。

Windowsではファイル用・ディレクトリ用のシンボリックリンクAPIを適切に使い分けること。

### 5.10 ファイル属性

通常ファイルについては、ファイル内容をコピーすることを必須とする。

アクセス権限、所有者、タイムスタンプなどのメタデータの完全な維持は本仕様の必須要件ではない。

## 6. DirectoryCopier：ディレクトリコピーオブジェクト

### 6.1 責務

指定されたディレクトリを再帰的にコピーする。

サブディレクトリ、空ディレクトリ、ファイルを含むディレクトリ構造を維持する。

### 6.2 構造体

```rust
pub struct DirectoryCopier {
    dir_path: PathBuf,
    dest_path: PathBuf,
}
```

### 6.3 コンストラクタ

```rust
impl DirectoryCopier {
    pub fn new(
        dir_path: PathBuf,
        dest_path: PathBuf,
    ) -> Self;
}
```

### 6.4 公開メソッド

```rust
impl DirectoryCopier {
    /// 元ディレクトリを残してコピーする。
    pub fn copy(&self) -> std::io::Result<()>;

    /// コピー完了後に元ディレクトリを削除する。
    pub fn move_dir(&self) -> std::io::Result<()>;
}
```

### 6.5 出力先の扱い

`dest_path` はコピー後のディレクトリそのものを指定する。

例えば、

```text
source/
    a.txt
    sub/
        b.txt

destination/
```

に対して `dest_path` を `destination/backup` とした場合、

```text
destination/
    backup/
        a.txt
        sub/
            b.txt
```

となる。

出力先の親ディレクトリが存在しない場合は作成する。

### 6.6 再帰コピー

以下を必ず実装する。

- サブディレクトリを再帰的にコピーする。
- 空ディレクトリをコピーする。
- ファイル内容をコピーする。
- ディレクトリ構造を維持する。
- ファイル名とディレクトリ名を変更しない。

### 6.7 シンボリックリンク

コピー元ディレクトリ内のシンボリックリンクは、リンク先をたどらず、リンクそのものをコピーする。

シンボリックリンクの先がファイルでもディレクトリでも、リンクそのものをコピーする。

`symlink_metadata` を使用して、リンク先ではなくリンク自体の種類を判定する。

シンボリックリンクを再帰走査してはならない。

これにより、循環参照による無限再帰を防止する。

### 6.8 一時ディレクトリへのコピー

コピー中は `dest_path` のディレクトリ名に `_temp` を追加したパスを使用する。

例：

```text
destination/backup
destination/backup_temp
```

最終出力先の既存データは、コピーが完了するまで変更しない。

コピー完了後、共通仕様に従って置き換える。

### 6.9 移動処理

`move_dir` は、コピーと最終出力先へのリネームが成功した後に元ディレクトリを削除する。

削除には再帰削除を使用する。

元ディレクトリの削除に失敗した場合はエラーを返す。

この場合、コピー済みの出力先は削除しない。

## 7. FilteredDirectoryCopier：除外設定付きディレクトリコピーオブジェクト

### 7.1 責務

`DirectoryCopier` と同じコピー・移動機能を提供する。

追加機能として、正規表現に一致するファイル名およびディレクトリ名をコピー対象から除外できる。

### 7.2 オプション構造体

オプションは将来的に拡張しやすいよう、独立した構造体で定義する。

```rust
pub struct FilteredDirectoryOptions {
    exclude_file_patterns: Vec<regex::Regex>,
    exclude_dir_patterns: Vec<regex::Regex>,
}
```

フィールドは外部から直接変更できないようにする。

必要に応じて読み取り用のアクセサを提供する。

### 7.3 構造体

```rust
pub struct FilteredDirectoryCopier {
    dir_path: PathBuf,
    dest_path: PathBuf,
    options: FilteredDirectoryOptions,
}
```

### 7.4 コンストラクタ

```rust
impl FilteredDirectoryCopier {
    /// デフォルトオプションで生成する。
    pub fn new(
        dir_path: PathBuf,
        dest_path: PathBuf,
    ) -> Self;

    /// 指定されたオプションで生成する。
    pub fn new_with(
        dir_path: PathBuf,
        dest_path: PathBuf,
        options: FilteredDirectoryOptions,
    ) -> Self;
}
```

### 7.5 オプション構造体のコンストラクタ

```rust
impl FilteredDirectoryOptions {
    pub fn new() -> Self;
}
```

`Default` も実装する。

### 7.6 メソッドチェーン

正規表現による除外条件を追加できるようにする。

```rust
impl FilteredDirectoryCopier {
    /// 除外するファイル名の正規表現を追加する。
    pub fn exclude_file(
        self,
        pattern: &str,
    ) -> std::io::Result<Self>;

    /// 除外するディレクトリ名の正規表現を追加する。
    pub fn exclude_dir(
        self,
        pattern: &str,
    ) -> std::io::Result<Self>;
}
```

正規表現のコンパイルは設定時に行う。

不正な正規表現の場合は `InvalidInput` を返す。

正規表現をコピー処理中に何度もコンパイルしてはならない。

既存の除外設定を保持し、新しいパターンを追加する。

### 7.7 除外対象の判定

正規表現の対象はパス全体ではなく、ファイル名またはディレクトリ名のみとする。

例：

```text
project/
    src/
        main.rs
    target/
        debug/
    logs/
        app.log
        error.log
    .git/
```

以下の設定の場合、

```rust
let copier = FilteredDirectoryCopier::new(
    PathBuf::from("project"),
    PathBuf::from("backup/project"),
)
.exclude_file(r"\.log$")?
.exclude_dir(r"^target$")?
.exclude_dir(r"^\.git$")?;
```

出力結果は以下とする。

```text
backup/
    project/
        src/
            main.rs
        logs/
```

### 7.8 ファイル除外ルール

- ファイル名だけを正規表現と比較する。
- 一致したファイルはコピーしない。
- 一致したファイルの親ディレクトリはコピーする。
- 複数のファイル除外パターンがある場合、いずれか1つに一致すれば除外する。

### 7.9 ディレクトリ除外ルール

- ディレクトリ名だけを正規表現と比較する。
- 一致したディレクトリはコピーしない。
- 一致したディレクトリ配下もすべてコピーしない。
- 複数のディレクトリ除外パターンがある場合、いずれか1つに一致すれば除外する。

### 7.10 シンボリックリンクの除外判定

シンボリックリンクはリンク先をたどらずに扱う。

リンク先がディレクトリであっても、リンク自体を1つのエントリとして扱う。

その名前に対してファイル除外パターンを適用する。

### 7.11 非Unicodeファイル名

正規表現の照合時はファイル名を `to_string_lossy()` で文字列化する。

この場合、非Unicode文字は置換文字を含む文字列として評価される。

### 7.12 コピー・移動API

```rust
impl FilteredDirectoryCopier {
    /// 除外設定に従ってディレクトリをコピーする。
    pub fn copy(&self) -> std::io::Result<()>;

    /// 除外設定に従ってコピーし、完了後に元ディレクトリを削除する。
    pub fn move_dir(&self) -> std::io::Result<()>;
}
```

処理内容は `DirectoryCopier` と同じとする。

ただし、コピー対象の判定に除外設定を適用する。

## 8. 同期処理の実装仕様

### 8.1 基本方針

すべてのファイル操作を同期処理として実装する。

ファイル操作にはRust標準ライブラリの `std::fs` を使用する。

以下の処理を同期的に実行する。

| 処理 | 使用API |
|---|---|
| ファイル読み書き | `std::fs` |
| ディレクトリ作成 | `std::fs::create_dir_all` |
| ディレクトリ走査 | `std::fs::read_dir` |
| メタデータ取得 | `std::fs` |
| ファイル削除 | `std::fs::remove_file` |
| ディレクトリ削除 | `std::fs::remove_dir_all` |
| リネーム | `std::fs::rename` |
| シンボリックリンク作成 | OS標準API |

シンボリックリンク作成には、OSごとの標準ライブラリAPIを使用する。

Windowsではファイル用・ディレクトリ用のシンボリックリンクAPIを適切に使い分けること。

### 8.2 ファイルコピー

通常ファイルのコピーには `std::fs::copy` または `std::fs::File` と `std::io` を使用する。

コピー先は必ず一時ファイルとする。

コピー完了後に、共通仕様に従って最終出力先に反映する。

### 8.3 ディレクトリコピー

`std::fs::read_dir` を使用してディレクトリを走査する。

サブディレクトリについては再帰的にコピー処理を実行する。

各エントリの種類は `symlink_metadata` を使用して判定する。

シンボリックリンクについてはリンク先をたどらないこと。

### 8.4 エラー処理と後始末

各ファイル操作のエラーを適切に処理する。

コピー処理に失敗した場合は、一時データを可能な限り削除する。

既存の出力先がある場合は、バックアップを復元する。

後始末のエラーによって元のエラーを隠してはならない。

## 9. コピー対象の種類と制約

### 9.1 対応対象

- 通常ファイル
- ディレクトリ
- 空ディレクトリ
- シンボリックリンク

### 9.2 非対応対象

通常ファイル、ディレクトリ、シンボリックリンク以外の特殊ファイル（ソケット、FIFO、デバイスファイルなど）はコピー対象外とする。

特殊ファイルを検出した場合は `Unsupported` 相当のエラーを返す。

### 9.3 シンボリックリンクの循環

リンク先を追跡しないため、リンクの循環による再帰コピーは発生させない。

## 10. テスト仕様

テストは単体テストと統合テストを実施する。

実ファイルシステムを汚さないよう、`tempfile` を利用して一時ディレクトリ内で実施する。

すべてのテストは同期APIを対象とする。

### 10.1 FileCopierのテスト

| No. | テスト内容 | 期待結果 |
|---|---|---|
| 1 | 通常ファイルのコピー | 内容が一致する |
| 2 | 出力先ディレクトリが存在しない | 自動作成される |
| 3 | 同名ファイルが存在する | 新しい内容に置き換わる |
| 4 | コピー元ファイルが存在しない | エラーになる |
| 5 | 一時ファイルが既に存在する | 古い一時ファイルが削除される |
| 6 | コピー失敗 | 一時ファイルが可能な限り削除される |
| 7 | コピー処理 | 元ファイルが残る |
| 8 | 移動処理 | コピー完了後に元ファイルが削除される |
| 9 | 移動先の作成に失敗 | 元ファイルが残る |
| 10 | 同一パスへのコピー | エラーになる |
| 11 | シンボリックリンク | リンク自体がコピーされる |
| 12 | 元ファイル削除失敗 | 出力先は維持される |

## 14. 実装上の禁止事項

以下は禁止する。

1. `lib.rs` にすべての処理を書くこと。
2. コピー途中で既存の出力先を削除すること。
3. コピー失敗時に元データを削除すること。
4. ディレクトリコピーでシンボリックリンクを無条件にたどること。
5. 除外正規表現をコピー処理中に毎回コンパイルすること。
6. ディレクトリ除外後に、その配下を走査すること。
7. エラー発生時に一時データの後始末を行わないこと。
8. 後始末のエラーによって元のエラーを隠すこと。
9. `unwrap()` や `expect()` を通常のファイル操作処理で使用すること。
10. `unsafe` を安易に使用すること。
11. 不要な外部クレートを追加すること。
12. 仕様にないメタデータ維持を必須要件として実装すること。
13. Tokioなどの非同期処理用クレートを追加すること。
14. 非同期APIを公開すること。
