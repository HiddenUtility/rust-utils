# Codex Implementation Specification
# Rust ZIP Compression Library

## 1. プロジェクト概要

### 1.1 目的

Rust を使用して、ファイルおよびディレクトリを ZIP 形式に圧縮するライブラリを実装する。

以下の3種類の圧縮機能を提供する。

1. ファイルを ZIP 圧縮する機能
2. ディレクトリを ZIP 圧縮する機能
3. 除外パターンや圧縮レベルなどの詳細設定が可能なディレクトリ ZIP 圧縮機能

さらに、すべての機能について同期版と非同期版を提供する。

### 1.2 開発環境・基本方針

- プログラミング言語：Rust
- 非同期ランタイム：Tokio
- プロジェクト形式：モノレポ
- 実装場所：`pjt/creates/create-name/`
- クレート名：既存のモノレポの命名規則に従う
- エラー型：`std::io::Error`
- 基本的な処理の戻り値：`std::io::Result<()>`

### 1.3 実装上の重要事項

以下を必ず守ること。

1. `lib.rs` にすべての実装を記述しない。責務ごとにファイルを分割する。
2. 公開APIには Rust の docstring（`///`）で仕様を記述する。
3. コメントアウトによる説明は極力避ける。
4. 同期版と非同期版の処理結果・エラー仕様を統一する。
5. ZIP の作成に失敗した場合、既存の出力ファイルを破壊しない。
6. 圧縮処理が完全に成功する前に元データを削除しない。
7. ファイルをすべてメモリに読み込んでから圧縮する実装は禁止する。ストリーミング形式で処理する。
8. 不必要な外部クレートを追加しない。
9. 既存のモノレポ構成や既存コードの規約を確認し、それらを壊さない。
10. 仕様に記載されていない機能を独自判断で追加しない。

## 2. 使用する外部クレート

以下のクレートを使用する。

| クレート | 用途 |
|---|---|
| `zip` | ZIP ファイルの作成 |
| `regex` | 除外対象の正規表現判定 |
| `tokio` | 非同期処理 |

### 2.1 ライセンス

以下のライセンスを許可する。

- MIT
- Apache-2.0
- BSD 系

採用するクレートおよび依存関係についてライセンスを確認すること。

### 2.2 依存関係の方針

- 可能な限り Pure Rust のクレートを優先する。
- ネイティブライブラリへの依存は極力避ける。
- ZIP の圧縮方式には Deflate を使用する。
- 不要な ZIP 圧縮方式や暗号化機能は有効にしない。
- `zip` クレートは必要な機能だけを有効にする。
- Deflate 実装について、可能であれば Pure Rust のバックエンドを選択する。
- 不必要な依存クレートを追加しない。

採用するクレートのバージョン、ライセンス、Cargo features を確認すること。

確認結果を `Cargo.toml` に反映し、`Cargo.lock` も適切に管理すること。

## 4. 共通仕様

### 4.1 圧縮レベル

デフォルトの圧縮レベルは `6` とする。

設定可能な値は以下の範囲とする。

```text
0 ～ 9
```

範囲外の値が指定された場合はエラーを返す。

エラーの種類は `std::io::ErrorKind::InvalidInput` とする。

圧縮レベルは ZIP の Deflate 圧縮に適用する。

レベル0も有効な値として扱う。

使用する `zip` クレートのAPIで、レベル0～9を正しく指定できることを確認すること。

### 4.2 ZIP 内部のディレクトリ構造

ディレクトリを圧縮する場合、ターゲットディレクトリ自体を ZIP 内部に含める。

例えば以下のディレクトリを圧縮する場合、

```text
target/
├── file1.txt
├── file2.txt
└── sub/
    └── file3.txt
```

ZIP 内部は以下の構造とする。

```text
target/
├── file1.txt
├── file2.txt
└── sub/
    └── file3.txt
```

ターゲットディレクトリの中身だけを ZIP のルートに配置してはならない。

ZIP 内のパス区切り文字は `/` に統一する。

空ディレクトリも ZIP 内に格納すること。

### 4.3 ファイルの読み込み

- ファイルはバッファを使用して逐次読み込む。
- ファイル全体を `Vec<u8>` などに読み込まない。
- 大容量ファイルでもメモリ使用量がファイルサイズに比例して増大しないようにする。
- 読み込みエラーは適切に呼び出し元へ返す。

### 4.4 出力先ディレクトリ

出力先の親ディレクトリが存在しない場合は作成する。

`std::fs::create_dir_all` を使用してよい。

作成に失敗した場合はエラーを返す。

### 4.5 一時ファイル

ZIP の作成中は、一時ファイルに書き込む。

一時ファイルは正式な出力ファイルのパスに `.temp` を追加したパスとする。

例：

```text
archive.zip
archive.zip.temp
```

一時ファイルが既に存在する場合は、圧縮開始前に削除する。

一時ファイルの削除に失敗した場合はエラーを返す。

ZIP の書き込み中にエラーが発生した場合は、一時ファイルを可能な限り削除する。

一時ファイルの削除に失敗しても、元のエラーを優先して返すこと。

### 4.6 既存の出力ファイル

同名の正式な出力ファイルが既に存在する場合でも、圧縮開始前に削除してはならない。

以下の手順を守ること。

1. 一時ファイルを作成する。
2. ZIP の圧縮処理を行う。
3. ZIP Writer の終了処理を行い、ZIP の書き込みを完了させる。
4. 完成した一時ファイルを正式な出力ファイルに置き換える。
5. 置き換えに成功したら処理を成功とする。

圧縮処理または ZIP の完成処理に失敗した場合、既存の正式な出力ファイルは残すこと。

#### 置き換え処理の注意事項

Windows と Unix 系 OS では、既存ファイルがある場合の `rename` の挙動が異なる。

そのため、OS の違いを考慮して既存ファイルの置き換えを実装すること。

以下の方式を基本とする。

1. 新しい ZIP が完成するまでは既存ファイルに触れない。
2. 既存ファイルを一時バックアップ名に変更する。
3. 新しい一時ファイルを正式な出力ファイルに変更する。
4. 変更に失敗した場合は既存ファイルを元の名前に戻す。
5. 新しい ZIP の配置に成功したらバックアップを削除する。

バックアップ名は既存ファイルや一時ファイルと衝突しないようにする。

バックアップの復元に失敗した場合は、バックアップファイルを削除せず、復旧に必要なパスをエラーメッセージに含めること。

バックアップの削除に失敗した場合もエラーとして扱い、元データの削除を実行しないこと。

既存出力ファイルが存在しない場合は、通常のリネームでよい。

この処理は共通関数として実装し、3種類の圧縮機能で再利用すること。

### 4.7 パスの検証

以下の場合は処理を開始せずエラーを返す。

- 入力元が存在しない。
- 入力元が要求された種類のファイル・ディレクトリではない。
- 入力元のパスが不正である。
- 出力先を作成できない。
- 出力先がディレクトリなど、要求するファイルとして扱えない。
- ZIP 内部のエントリ名を安全な形式に変換できない。

エラーには適切な `std::io::ErrorKind` を使用する。

入力元がシンボリックリンクである場合は、シンボリックリンクの扱いに関する共通仕様に従う。

### 4.8 シンボリックリンク

シンボリックリンクは ZIP に含めない。

ディレクトリを再帰的に走査する際は、シンボリックリンクを検出した場合、そのリンクを無視する。

リンク先をたどってはならない。

入力元のルート自体がシンボリックリンクの場合も、圧縮対象として扱わず `InvalidInput` を返す。

### 4.9 その他のファイル種別

通常ファイルとディレクトリのみを対象とする。

FIFO、ソケット、デバイスファイルなどは ZIP に含めない。

### 4.10 出力先と入力元の競合

ディレクトリ圧縮の場合、出力先 ZIP および一時ファイルが入力元ディレクトリ配下に配置されることを禁止する。

出力先が入力元の内部にある場合は `InvalidInput` を返す。

これにより、一時ファイルや完成済み ZIP 自体が圧縮対象に含まれることを防止する。

パスの比較は、可能な範囲で正規化したパスを使用すること。

同一の出力先に対する複数の圧縮処理の同時実行はサポート対象外とする。

## 5. 機能1：ファイルの ZIP 圧縮

### 5.1 概要

指定したファイルを ZIP 形式に圧縮するオブジェクトを実装する。

### 5.2 引数

```rust
file_path: PathBuf
dir_path: PathBuf
```

| 引数 | 内容 |
|---|---|
| `file_path` | 圧縮対象のファイルパス |
| `dir_path` | ZIP ファイルの出力先ディレクトリ |

### 5.3 出力ファイル名

出力 ZIP ファイル名は、元ファイル名の拡張子を `.zip` に置き換えた名前とする。

元ファイル名の拡張子を残したまま `.zip` を追加してはならない。

Rust の `Path::file_stem()` を使用して元ファイル名から拡張子を除去し、その後ろに `.zip` を追加する。

例：

| 入力ファイル | 出力ファイル |
|---|---|
| `sample.txt` | `sample.zip` |
| `image.png` | `image.zip` |
| `archive.tar.gz` | `archive.tar.zip` |
| `README` | `README.zip` |

出力先ディレクトリが `output/` の場合、出力パスは以下とする。

```text
output/sample.zip
```

一時ファイルは以下とする。

```text
output/sample.zip.temp
```

ファイル名の生成処理は共通関数として実装し、同期版・非同期版で同じ処理を使用すること。

### 5.4 ZIP 内部の構造

例えば `sample.txt` を圧縮した場合、ZIP 内部のエントリ名は以下とする。

```text
sample.txt
```

元ファイル名を維持すること。

ZIP 内部に出力先ディレクトリのパスを含めてはならない。

### 5.5 圧縮処理

以下の順序で処理すること。

1. 入力ファイルの存在を確認する。
2. 入力ファイルが通常ファイルであることを確認する。
3. 入力ファイルがシンボリックリンクではないことを確認する。
4. 出力先ディレクトリを作成する。
5. 既存の一時ファイルを削除する。
6. 一時 ZIP ファイルを作成する。
7. 圧縮レベル6でファイルを ZIP に格納する。
8. ZIP Writer の終了処理を実行する。
9. 一時 ZIP ファイルを正式な ZIP ファイルに置き換える。

### 5.6 提供する関数

以下の2種類を実装する。

| 関数 | 動作 |
|---|---|
| `compress` | ZIP 圧縮する。元ファイルは残す |
| `compress_and_remove_source` | ZIP 圧縮成功後に元ファイルを削除する |

元ファイルを削除する関数は、正式な ZIP ファイルへの置き換えまで成功した場合のみ削除を行う。

削除に失敗した場合は `std::io::Error` を返す。

### 5.7 同期版・非同期版

以下の4つのメソッドを提供する。

```rust
compress()
compress_and_remove_source()

compress_async()
compress_and_remove_source_async()
```

非同期版の実装については第8章に従う。

## 6. 機能2：ディレクトリの ZIP 圧縮

### 6.1 概要

指定したディレクトリを再帰的に ZIP 圧縮するオブジェクトを実装する。

### 6.2 引数

```rust
dir_path: PathBuf
zip_path: PathBuf
```

| 引数 | 内容 |
|---|---|
| `dir_path` | 圧縮対象のディレクトリ |
| `zip_path` | 出力する ZIP ファイルのパス |

出力ファイルの拡張子は `.zip` に限定しない。

例えば以下を許可する。

```text
archive.zip
archive.backup
archive.data
archive
```

指定された `zip_path` をそのまま正式な出力先として使用する。

### 6.3 ZIP 内部の構造

ターゲットディレクトリ自体を ZIP 内部に含める。

例えば、

```text
target/
├── a.txt
├── b.txt
└── sub/
    └── c.txt
```

以下の構造で格納する。

```text
target/
├── a.txt
├── b.txt
└── sub/
    └── c.txt
```

ZIP 内部のルートに `target` ディレクトリが存在すること。

### 6.4 圧縮処理

以下の順序で処理すること。

1. 入力ディレクトリの存在を確認する。
2. 入力ディレクトリであることを確認する。
3. 入力ディレクトリがシンボリックリンクではないことを確認する。
4. 出力先の親ディレクトリを作成する。
5. 出力先と入力元の競合を確認する。
6. 既存の一時ファイルを削除する。
7. 一時 ZIP ファイルを作成する。
8. ディレクトリを再帰的に走査する。
9. 通常ファイルを ZIP に追加する。
10. 空ディレクトリも ZIP に追加する。
11. ZIP Writer の終了処理を実行する。
12. 一時 ZIP ファイルを正式な ZIP ファイルに置き換える。

一時ファイルのパスは以下とする。

```text
{zip_path}.temp
```

例：

```text
output/archive.zip
output/archive.zip.temp
```

### 6.5 ディレクトリ走査

標準ライブラリの `std::fs::read_dir` などを使用して再帰的に走査してよい。

以下を守ること。

- サブディレクトリを再帰的に走査する。
- 通常ファイルを ZIP に追加する。
- 空ディレクトリも ZIP に追加する。
- シンボリックリンクは無視する。
- ZIP 内部のディレクトリ構造を維持する。
- パス区切り文字は `/` に統一する。
- ファイルをメモリに全展開しない。
- ファイル名の UTF-8 変換に失敗した場合は `InvalidData` を返す。
- 各ディレクトリ内のエントリをファイル名順にソートして処理する。

ディレクトリのエントリ名は、ターゲットディレクトリ名をルートとして生成すること。

例えば、ターゲットが `data` の場合、

```text
data/file1.txt
data/sub/file2.txt
```

とする。

### 6.6 空ディレクトリ

ファイルが存在しないディレクトリであっても ZIP に格納する。

例えば、

```text
target/
└── empty/
```

を圧縮した場合、ZIP 内部には以下のエントリを含める。

```text
target/
target/empty/
```

ルートディレクトリも必ず格納すること。

### 6.7 提供する関数

以下の2種類を実装する。

| 関数 | 動作 |
|---|---|
| `compress` | ZIP 圧縮する。元ディレクトリは残す |
| `compress_and_remove_source` | ZIP 圧縮成功後に元ディレクトリを削除する |

元ディレクトリの削除には `std::fs::remove_dir_all` を使用してよい。

削除は正式な ZIP ファイルの作成が完了した後に実行する。

削除に失敗した場合は `std::io::Error` を返す。

削除途中にエラーが発生し、一部の元データだけが削除された状態になることは許容する。

### 6.8 同期版・非同期版

以下の4つのメソッドを提供する。

```rust
compress()
compress_and_remove_source()

compress_async()
compress_and_remove_source_async()
```

## 7. 機能3：詳細設定付きディレクトリ ZIP 圧縮

### 7.1 概要

機能2のディレクトリ圧縮に対して、圧縮レベルや除外パターンなどのオプションを設定できる機能を追加する。

将来のオプション追加を容易にするため、設定値は専用の構造体にまとめる。

### 7.2 オプション構造体

以下の構造を基本とする。

```rust
pub struct ZipOptions {
    compression_level: u32,
    exclude_file_patterns: Vec<String>,
    exclude_directory_patterns: Vec<String>,
}
```

各フィールドの意味は以下のとおり。

| フィールド | 説明 | デフォルト |
|---|---|---|
| `compression_level` | 圧縮レベル | 6 |
| `exclude_file_patterns` | 除外するファイル名の正規表現 | 空配列 |
| `exclude_directory_patterns` | 除外するディレクトリ名の正規表現 | 空配列 |

フィールドは原則として非公開とし、公開メソッドから設定する。

`Default` を実装すること。

### 7.3 コンストラクタ

以下の2種類を実装する。

#### new

```rust
new(
    dir_path: PathBuf,
    zip_path: PathBuf,
) -> Self
```

デフォルトオプションを使用して初期化する。

#### new_with

```rust
new_with(
    dir_path: PathBuf,
    zip_path: PathBuf,
    options: ZipOptions,
) -> Self
```

指定されたオプションを使用して初期化する。

オプションの妥当性は圧縮開始前に検証すること。

### 7.4 メソッドチェーン

生成したオブジェクトに対してメソッドチェーンでオプションを変更できるようにする。

以下の設定機能を提供する。

#### 7.4.1 圧縮レベルの設定

```rust
with_compression_level(level: u32) -> std::io::Result<Self>
```

圧縮レベルを設定する。

有効範囲は0～9。

範囲外の値を設定した場合は `InvalidInput` を返す。

#### 7.4.2 ファイル名の除外パターン

```rust
with_exclude_file_pattern(
    pattern: impl Into<String>,
) -> std::io::Result<Self>
```

ZIP に含めないファイル名の正規表現を追加する。

複数回呼び出すことで複数のパターンを登録できる。

正規表現が不正な場合は `InvalidInput` を返す。

#### 7.4.3 ディレクトリ名の除外パターン

```rust
with_exclude_directory_pattern(
    pattern: impl Into<String>,
) -> std::io::Result<Self>
```

ZIP に含めないディレクトリ名の正規表現を追加する。

複数回呼び出すことで複数のパターンを登録できる。

正規表現が不正な場合は `InvalidInput` を返す。

#### 7.4.4 メソッドチェーンの使用例

以下のように使用できるAPIとする。

```rust
let compressor = ConfigurableDirectoryZipCompressor::new(
    PathBuf::from("target"),
    PathBuf::from("output/archive.zip"),
)
.with_compression_level(9)?
.with_exclude_file_pattern(r"\.log$")?
.with_exclude_file_pattern(r"\.tmp$")?
.with_exclude_directory_pattern(r"^cache$")?;
```

設定メソッドは所有権を移動するビルダーパターンで実装する。

`ZipOptions` に対しても同等の設定メソッドを提供すること。

### 7.5 正規表現による除外処理

正規表現の判定には `regex` クレートを使用する。

#### ファイル名パターン

ファイル名のベース名だけを対象に判定する。

パス全体や親ディレクトリ名は判定対象に含めない。

例：

```text
target/
├── app.log
├── data.txt
└── sub/
    ├── error.log
    └── result.txt
```

以下のパターンを設定する。

```rust
r"\.log$"
```

除外されるファイル：

```text
app.log
sub/error.log
```

#### ディレクトリ名パターン

ディレクトリ名のベース名だけを対象に判定する。

例：

```text
target/
├── data/
│   └── file1.txt
├── cache/
│   └── file2.txt
└── backup/
    └── file3.txt
```

以下のパターンを設定する。

```rust
r"^cache$"
```

除外されるもの：

```text
cache/
cache/file2.txt
```

ディレクトリが除外された場合、そのディレクトリ配下は再帰的に走査せず、すべて除外すること。

#### 複数パターンの扱い

登録されている正規表現のうち、いずれか1つに一致した場合は除外する。

```text
pattern1 に一致
OR
pattern2 に一致
OR
pattern3 に一致
```

#### 正規表現のコンパイル

正規表現は圧縮処理の開始前にすべてコンパイルする。

正規表現が不正な場合は `InvalidInput` を返す。

不正な正規表現が存在する場合、ZIP の作成を開始してはならない。

#### 除外処理の注意事項

- ファイル名とディレクトリ名の正規表現は別々に管理する。
- ファイル名の正規表現でディレクトリ名を判定しない。
- ディレクトリ名の正規表現でファイル名を判定しない。
- ベース名のみで判定する。
- 大文字・小文字の区別は `regex` クレートの標準仕様に従う。
- 除外されたディレクトリの中身は走査しない。
- 複数パターンのいずれかに一致した場合は除外する。

### 7.6 圧縮処理

基本的な処理手順は機能2と同じとする。

ただし、ZIP に追加する前に除外判定を実施する。

処理順序は以下とする。

1. 入力ディレクトリを検証する。
2. 出力先を検証する。
3. オプションを検証する。
4. 登録された正規表現をコンパイルする。
5. 出力先の親ディレクトリを作成する。
6. 古い一時ファイルを削除する。
7. 新しい一時 ZIP ファイルを作成する。
8. ディレクトリを再帰的に走査する。
9. シンボリックリンクを無視する。
10. ディレクトリの除外パターンを判定する。
11. 除外されたディレクトリは走査しない。
12. ファイルの除外パターンを判定する。
13. 除外されなかったファイルを ZIP に追加する。
14. 空ディレクトリを ZIP に追加する。
15. ZIP Writer の終了処理を実行する。
16. 一時ファイルを正式な出力ファイルに置き換える。

### 7.7 提供する関数

以下の2種類を実装する。

| 関数 | 動作 |
|---|---|
| `compress` | ZIP 圧縮する。元ディレクトリは残す |
| `compress_and_remove_source` | ZIP 圧縮成功後に元ディレクトリを削除する |

### 7.8 同期版・非同期版

以下の4つのメソッドを提供する。

```rust
compress()
compress_and_remove_source()

compress_async()
compress_and_remove_source_async()
```

## 8. 非同期版の実装

### 8.1 基本方針

Tokio を利用して非同期版を実装する。

ただし、ZIP クレートによる圧縮処理は同期処理として実装する。

非同期版では `tokio::task::spawn_blocking` を使用して同期処理を実行する。

ZIP 圧縮処理を Tokio の Executor 上で直接実行してはならない。

### 8.2 実装方式

同期版と非同期版で処理ロジックを重複実装しないこと。

以下の構造とする。

```text
公開API
  |
  +-- 同期版
  |     |
  |     +-- 共通ZIP圧縮処理
  |
  +-- 非同期版
        |
        +-- tokio::task::spawn_blocking
                |
                +-- 同期版の処理
```

### 8.3 非同期版の実装例

概念的には以下の形式とする。

```rust
pub async fn compress_async(&self) -> std::io::Result<()> {
    let compressor = self.clone();

    tokio::task::spawn_blocking(move || {
        compressor.compress()
    })
    .await
    .map_err(|err| {
        std::io::Error::new(
            std::io::ErrorKind::Other,
            err.to_string(),
        )
    })?
}
```

実際の実装では、必要に応じて所有権や `Clone` の設計を調整すること。

`std::io::Error` を含む値を不用意に複製しないこと。

### 8.4 JoinError の扱い

`spawn_blocking` の JoinError は `std::io::Error` に変換する。

通常の ZIP 圧縮処理から返された `std::io::Error` は、そのまま呼び出し元へ返す。

JoinError と ZIP 圧縮処理自体のエラーを混同しないこと。

### 8.5 非同期版の対象

以下のすべての処理について非同期版を実装する。

| 機能 | 同期版 | 非同期版 |
|---|---|---|
| ファイル圧縮 | 必須 | 必須 |
| ファイル圧縮＋元ファイル削除 | 必須 | 必須 |
| ディレクトリ圧縮 | 必須 | 必須 |
| ディレクトリ圧縮＋元ディレクトリ削除 | 必須 | 必須 |
| 詳細設定付きディレクトリ圧縮 | 必須 | 必須 |
| 詳細設定付き圧縮＋元ディレクトリ削除 | 必須 | 必須 |

### 8.6 同期版と非同期版の一致

以下を保証する。

- 出力 ZIP の内容が同じである。
- 圧縮レベルが同じである。
- 除外パターンの動作が同じである。
- エラーの発生条件が同じである。
- 元データの削除タイミングが同じである。
- 一時ファイルの後始末が同じである。

## 9. 元データ削除処理

### 9.1 基本方針

元データを削除する関数では、ZIP の完成と正式な出力ファイルへの置き換えが成功した場合のみ削除処理を実行する。

### 9.2 処理手順

必ず以下の順序を守る。

1. ZIP の作成を開始する。
2. ZIP の書き込みを完了する。
3. 一時 ZIP ファイルを正式な出力ファイルにリネームする。
4. ここまでの処理がすべて成功したことを確認する。
5. 元データを削除する。
6. 削除に成功した場合は `Ok(())` を返す。

### 9.3 削除方法

ファイルの場合：

```rust
std::fs::remove_file(path)
```

ディレクトリの場合：

```rust
std::fs::remove_dir_all(path)
```

### 9.4 エラー時の動作

| エラー発生箇所 | 元データ | ZIP |
|---|---|---|
| ZIP 作成開始前 | 残す | 変更しない |
| ZIP 書き込み中 | 残す | 既存 ZIP を維持 |
| ZIP 完成処理 | 残す | 既存 ZIP を維持 |
| 正式ファイルへの置き換え | 残す | 可能な限り既存 ZIP を復元 |
| 元データ削除 | 一部削除の可能性あり | 完成済み ZIP を残す |

元データ削除中にエラーが発生した場合、一部のデータだけが削除された状態になることは許容する。

削除エラーが発生しても、完成済み ZIP は削除してはならない。

## 10. エラー処理

### 10.1 エラー型

すべての公開処理のエラー型は以下とする。

```rust
std::io::Error
```

基本的な処理結果は以下の形式とする。

```rust
std::io::Result<()>
```

コンストラクタやビルダーメソッドなど、値を返す必要があるAPIについては、その戻り値の型に適した `std::io::Result<Self>` などを使用してよい。

独自の公開エラー型は作成しない。

### 10.2 エラー変換

`zip` クレートや `regex` クレートから発生するエラーは `std::io::Error` に変換する。

基本的な変換方針：

| エラー | ErrorKind |
|---|---|
| 不正な入力パス | InvalidInput |
| 圧縮レベルが範囲外 | InvalidInput |
| 不正な正規表現 | InvalidInput |
| ZIP 内部パスの不正 | InvalidData |
| ファイル・ディレクトリが存在しない | NotFound |
| 権限不足 | PermissionDenied |
| ファイル操作失敗 | 元の ErrorKind を可能な限り維持 |
| ZIP ライブラリエラー | InvalidData または Other |
| spawn_blocking の JoinError | Other |

可能な限り元のエラー情報を維持すること。

エラーメッセージには処理対象のパスや処理内容など、原因の特定に必要な情報を含める。

### 10.3 エラー発生時の後始末

ZIP 作成処理中にエラーが発生した場合は、以下を守る。

- ZIP Writer を適切に終了できる場合は終了する。
- 一時ファイルを可能な限り削除する。
- 既存の正式な ZIP ファイルを変更しない。
- 元ファイル・ディレクトリを削除しない。
- 後始末のエラーによって元のエラーを上書きしない。

一時ファイルの後始末は、エラー発生時だけでなく、正常終了時にも残存していないことを確認する。

## 13. テスト仕様

単体テストおよび異常系テストを実装すること。

テスト用の一時ディレクトリはテストごとに独立して用意する。

テスト終了後は作成したファイル・ディレクトリを削除すること。

ZIP の内容を検証する場合は `zip` クレートを使用して読み込み、実際のエントリ名と内容を確認すること。

### 13.1 ファイル圧縮テスト

以下をテストする。

- 通常ファイルを ZIP 圧縮できる。
- ZIP 内部のファイル名が元ファイル名と一致する。
- `sample.txt` が `sample.zip` になる。
- `image.png` が `image.zip` になる。
- `archive.tar.gz` が `archive.tar.zip` になる。
- 拡張子がないファイルが `README.zip` になる。
- 出力先ディレクトリが存在しない場合に自動作成される。
- 既存の ZIP ファイルを新しい ZIP で置き換えられる。
- 元ファイルを残す関数では元ファイルが残る。
- 元ファイルを削除する関数では元ファイルが削除される。

### 13.2 ディレクトリ圧縮テスト

以下をテストする。

- 通常のディレクトリを ZIP 圧縮できる。
- サブディレクトリが再帰的に圧縮される。
- ZIP 内部にターゲットディレクトリ自体が含まれる。
- ZIP 内部のパス区切り文字が `/` である。
- 空ディレクトリが ZIP に含まれる。
- 複数階層のディレクトリを圧縮できる。
- 大容量ファイルをストリーミングで圧縮できる。
- 元ディレクトリを残す関数では元ディレクトリが残る。
- 元ディレクトリを削除する関数では元ディレクトリが削除される。

### 13.3 詳細設定テスト

以下をテストする。

- デフォルト圧縮レベルが6である。
- 圧縮レベル0を指定できる。
- 圧縮レベル9を指定できる。
- 圧縮レベル10を指定するとエラーになる。
- 圧縮レベルが範囲外の場合は ZIP を作成しない。
- ファイル名の正規表現で除外できる。
- ディレクトリ名の正規表現で除外できる。
- 複数のファイル除外パターンを登録できる。
- 複数のディレクトリ除外パターンを登録できる。
- いずれかのパターンに一致すれば除外される。
- ファイル名の判定がベース名だけを対象にしている。
- ディレクトリ名の判定がベース名だけを対象にしている。
- 除外されたディレクトリ配下がすべて除外される。
- 除外されなかったファイルは ZIP に含まれる。
- 不正な正規表現を指定するとエラーになる。
- 不正な正規表現の場合は ZIP の作成が開始されない。
- 除外されたディレクトリ内のファイルを走査しない。

### 13.4 一時ファイルテスト

以下をテストする。

- 既存の `.temp` ファイルが削除される。

- 圧縮成功後に `.temp` ファイルが正式な出力ファイルに変更される。

- 圧縮失敗時に `.temp` ファイルが可能な限り削除される。

### 13.5 既存出力ファイル保護テスト

特に重要なテストである。

以下を必ずテストする。

1. 既存の ZIP ファイルを作成する。
2. 新しい ZIP の圧縮処理を開始する。
3. 圧縮途中にエラーを発生させる。

- ZIP 内部のパスが不正な場合。
- ファイルの読み込み中にエラーが発生した場合。
- ZIP 書き込み中にエラーが発生した場合。
- ZIP の終了処理に失敗した場合。

### 13.9 非同期版テスト

同期版と非同期版の両方について以下を確認する。

- ZIP の内容が同じである。
- ファイル名が同じである。
- 除外パターンの動作が同じである。
- エラーの種類が同じである。
- 元データの削除動作が同じである。
- 一時ファイルの後始末が同じである。

Tokio のテストランタイムを使用すること。

```rust
#[tokio::test]
async fn test_compress_async() {
    // テスト実装
}
```

## 14. 実装時の注意事項

### 14.1 ZIP Writer の終了処理

ZIP の作成では、単にファイルへの書き込みが終わっただけでは完成とはみなさない。

ZIP Writer の終了処理を必ず実行すること。

終了処理の結果を確認し、成功した場合のみ一時ファイルを正式な出力ファイルに変更すること。

### 14.2 ファイル・ディレクトリ走査

- `read_dir` のエラーを無視しない。
- ファイルの読み込みエラーを無視しない。
- ZIP への書き込みエラーを無視しない。
- 不正なパスを黙ってスキップしない。
- シンボリックリンクだけは仕様に従って明示的に無視する。
- ディレクトリ走査の順序を安定させる。

### 14.3 パスの安全性

ZIP 内部のエントリ名は、入力元ディレクトリを基準に生成すること。

ZIP 内部に以下のようなパスが入らないようにする。

```text
../outside.txt
/absolute/path.txt
```

ZIP 内部のパスは相対パスとし、ルートディレクトリからの構造を維持すること。

### 14.4 OS 互換性

Windows と Unix 系 OS の両方で動作すること。

特に以下に注意する。

- ファイルのリネーム
- 既存ファイルの置き換え
- パス区切り文字
- ファイル名の扱い
- シンボリックリンク
- ファイル削除

### 14.5 同時実行

同一の出力先を使用する複数の圧縮処理を同時に実行した場合の動作は保証しない。

同一出力先の競合を検出できる場合は `AlreadyExists` など適切なエラーを返すこと。

異なる出力先を使用する圧縮処理は並行して実行できる設計とする。

特に以下の点を厳守すること。

1. ファイル圧縮時は元ファイルの拡張子を `.zip` に置き換える。例えば `sample.txt` は `sample.zip` とする。
2. ディレクトリ圧縮時はターゲットディレクトリ自体を ZIP 内部に含める。

4. 一時ファイルを使用して ZIP を作成する。
5. ZIP の完成と正式な出力ファイルへの置き換えが成功してから元データを削除する。
6. 除外パターンはファイル名・ディレクトリ名のベース名だけで判定する。
7. シンボリックリンクは無視する。
8. 非同期版は `tokio::task::spawn_blocking` を使用する。
9. 同期版と非同期版で処理ロジックを重複実装しない。
10. すべての公開処理で `std::io::Error` を使用する。

実装後はテスト・フォーマット・Lint・ドキュメント生成を実行すること。

テストに失敗した場合は原因を調査して修正すること。
