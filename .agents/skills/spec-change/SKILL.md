# spec-change

## 指示内容
1. **仕様のヒアリング**: ユーザーに対し、「どの機能（またはクレート）を変更するか」「現在の仕様は何か」「変更後の新しい仕様は何か」の3点を必ず確認してください。
2. **現状分析**: 対象となるソースコードと既存のテストコードを読み込み、現在の実装を正確に把握してください。
3. **テストの作成・更新 (TDD Step 1)**: 新しい仕様に基づき、テストコード（ユニットテストまたは統合テスト）を修正または新規作成してください。この際、実装が伴っていないためテストが失敗することを確認してください。
4. **実装 (TDD Step 2)**: テストがパスするように、ソースコードを修正または新規実装してください。
5. **品質ガード**: 実装完了後、以下のコマンドを実行して品質を確認してください。
    - `cargo fmt --check`
    - `cargo clippy -- -D warnings`
    - `cargo test --workspace`
6. **振り返りへの連携**: すべての工程（品質ガード含む）が正常に完了したら、`retro` スキルを呼び出し、作業の振り返りを行ってください。
