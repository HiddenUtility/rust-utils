# implement-util

## 1. 目的

仕様に基づき、堅牢で高品質な Rust のユーティリティ機能を TDD (Test-Driven Development) のプロセスに従って実装する。

## 2. 入力

| 入力 | 必須 | 説明 |
|---|---|---|
| 機能仕様 | 必須 | 実装したい機能の詳細（目的、インターフェース、期待される挙動、エラー条件など） |
| 対象クレート/パス | 必須 | 実装対象となるクレート名、または既存のファイルパス |

## 3. 手順

### STEP 1. 仕様の理解とインターフェース設計

1. 与えられた仕様を詳細に読み解く。
2. 実装すべき公開インターフェース（関数、構造体、トレイト、列挙型など）を検討し、仕様に沿った設計を行う。
3. 必要に応じて、設計内容をユーザーに確認する。

### STEP 2. テストの作成 (Red)

1. 仕様に基づき、まず**失敗するテスト**を作成する。
2. テストは以下の内容を網羅すること：
    - **正常系**: 仕様通りの入力に対する期待される出力。
    - **境界値**: データの最小値、最大値、空の状態など。
    - **異常系**: 不正な入力やエラーが発生すべきケース。
3. **テスト命名規則**: `test_[関数名]_[期待される結果]` の形式とする (例: `test_add_should_be_5`)。
4. `cargo test` を実行し、テストが意図通りに失敗することを確認する。

### STEP 3. 実装 (Green)

1. テストをパスさせるために、最小限の実装を行う。
2. **エラー処理方針**:
    - `Result` 型を適切に使用する。
    - `thiserror` 等を用いて明示的なエラー型を定義する。
    - `unwrap()` や `expect()` の安易な使用は避け、原則として禁止する。
3. 実装が完了したら、再度 `cargo test` を実行し、作成したテストがすべてパスすることを確認する。

### STEP 4. 品質ガード (Refactor & Check)

1. コードの品質を担保するため、以下のコマンドをすべて実行する：
    - `cargo fmt --check` (フォーマット確認)
    - `cargo clippy -- -D warnings` (リンターによる静的解析)
    - `cargo test --workspace` (ワークスペース全体のテスト確認)
2. 品質ガードがエラーを返した場合、修正して再度実行し、すべてパスすることを確認する。

### STEP 5. 振り返り (Retro)

1. 作業がすべて完了し、品質が担保されたことを確認した後、`retro` スキルを呼び出し、実行結果の振り返りを行う。

## 4. 禁止事項

- テストを作成せずに実装を開始すること。
- `unwrap()` や `expect()` を、不変条件のチェック等の限定的なケースを除いて使用すること。
- 品質ガード（fmt, clippy, test）がエラーを返している状態で作業を完了すること。
- 既存のコードの意図を無視した、破壊的な変更を行うこと。
